## 1. 产品概述

### 1.1 一句话定位

一个**零配置、零账号、纯本地**的 TXT 阅读器：导入文件就能读，关掉再打开接着上次的位置。

### 1.2 要解决的问题

长篇小说、笔记、文稿大多以 `.txt` 形式在本地流转，但常见阅读工具存在三个摩擦点：

1. **需要登录**：为读一个本地文件，被迫注册账号、联网同步
2. **需要上传**：私人文稿被传到第三方服务器，隐私不可控
3. **打断后丢失位置**：网页阅读器刷新即从头开始，长文阅读体验断裂

马克阅读的取舍是：**放弃格式丰富度与功能广度，换取极低的使用门槛和确定的数据归属**。

### 1.3 目标用户

| 用户类型 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 小说读者 | 阅读本地下载的 TXT 小说 | 连续读、记住进度 |
| 文稿作者 | 通读自己或他人交付的 TXT 稿件 | 快速打开、不联网 |
| 隐私敏感用户 | 内部资料、个人笔记 | 数据不出本机 |

### 1.4 设计原则

1. **本地优先**：所有书籍、进度只存在浏览器 IndexedDB，无后端、无网络请求
2. **范围克制**：只做"读"这一件事，凡不服务于闭环的功能一律砍掉
3. **打开即用**：无引导页、无设置面板、无登录流程
4. **诚实降级**：做不到精确的能力（如字符级定位）明确说明误差范围，不假装精确

## 2. 范围定义

### 2.1 MVP 范围（已实现）

| 能力 | 说明 | 状态 |
| --- | --- | --- |
| 导入 TXT | 按钮选择或拖拽，支持多选 | ✅ |
| 编码识别 | UTF-8 / GB18030 自动判断，去除 BOM | ✅ |
| 书架列表 | 书名、大小、字数、已读百分比 | ✅ |
| 阅读视图 | 全文连续滚动，保留原始换行段落 | ✅ |
| 进度记忆 | 按全文字符偏移记录，关闭后恢复 | ✅ |
| 删除书籍 | 从书架移除并清理进度 | ✅ |

### 2.2 明确不做（及理由）

| 不做的功能 | 理由 |
| --- | --- |
| EPUB / PDF 支持 | 需要独立渲染引擎（EPUB 重排、PDF 坐标映射），是 MVP 周期的 2-3 倍 |
| 目录 / 章节切分 | 纯文本无可靠结构，切分规则易误判；连续滚动已能满足阅读 |
| 划线 / 笔记 / 书签 | 属于"二次加工"需求，非"读完一本书"的必要条件 |
| 主题 / 字号调节 | 通过固定排版参数保证稳定输出，避免设置面板带来的复杂度 |
| 账号 / 云同步 | 引入后端等于推翻"本地优先"定位，且开发成本翻倍 |
| 搜索 / 更换字体 | 文件量与个性化需求尚未被验证，暂无收益 |

> **决策记录**：初版曾计划支持 EPUB、章节导航与批注（对应初期 M1 实现），后经评估全部移除。相关代码（`splitChapters`、`annotations` 表）已删除，数据层从 v1 升级到 v2。

## 3. 用户流程

### 3.1 首次使用

```text
打开页面 → 书架空态（提示导入）
        → 点击「导入 TXT」或拖入文件
        → 系统解码、入库
        → 书架出现书籍卡片（进度 0%）
        → 点击卡片进入阅读页
```

### 3.2 再次阅读

```text
打开页面 → 书架显示所有书籍及已读百分比
        → 点击某本 → 阅读页自动定位到上次位置
        → 滚动阅读，进度静默保存
        → 点击「← 书架」返回，最终位置落库
```

### 3.3 删除书籍

```text
书架卡片右上角 ✕ → 立即删除（含进度）→ 列表刷新
```

### 3.4 异常分支

| 场景 | 处理 |
| --- | --- |
| 选择非 `.txt` 文件 | 拦截并提示「只支持 .txt 格式的文件」 |
| 混合选择（含非 txt） | 过滤出 txt 文件继续导入，忽略其余 |
| 文件解码失败 | 回退 GB18030 解码；仍异常则提示导入失败 |
| 打开已删除的书 | 显示「书籍不存在，可能已被删除」 |

## 4. 功能规格

### 4.1 导入

| 项 | 规格 |
| --- | --- |
| 触发方式 | 顶栏「导入 TXT」按钮；全页面拖拽 |
| 文件类型 | 后缀匹配 `.txt`（不区分大小写） |
| 多选 | 支持，按选择顺序依次导入 |
| 书名来源 | 文件名去掉 `.txt` 后缀；为空时显示「未命名」 |
| 编码策略 | 先用 `TextDecoder('utf-8', { fatal: true })` 严格解码，失败回退 `gb18030`；识别到 UTF-8 BOM 时直接判定 UTF-8 |
| 存储 | 全文以字符串形式存入 IndexedDB |
| 导入中状态 | 按钮文案变为「导入中…」并禁用，避免重复触发 |

### 4.2 书架

| 项 | 规格 |
| --- | --- |
| 布局 | 响应式网格，宽屏多列，窄屏单列 |
| 卡片信息 | 封面占位（TXT 标识）、书名（最多两行省略）、`KB · 字数`、进度条、`已读 N%` |
| 排序 | 按导入时间倒序（最近导入在最前） |
| 点击 | 进入阅读页 |
| 键盘 | 卡片可聚焦，`Enter` 进入阅读页 |

### 4.3 阅读

| 项 | 规格 |
| --- | --- |
| 布局 | 顶栏（返回按钮 + 书名）固定，正文区域独立滚动 |
| 排版 | 正文最大宽度 760px 居中，字号 17px，行高 1.95，保留原始换行（`white-space: pre-wrap`） |
| 主题 | 单一浅色主题（米白背景），不提供切换 |
| 字号 | 固定，不提供调节 |
| 移动端 | 窄屏下内边距与字号自动收窄 |

### 4.4 进度记忆

| 项 | 规格 |
| --- | --- |
| 记录内容 | `charOffset`（全文中的字符偏移量） |
| 保存时机 | 滚动停止 400ms 后；离开阅读页时兜底保存 |
| 恢复方式 | 打开书籍时读取 `charOffset`，换算为滚动比例后定位 |
| 展示 | 书架卡片显示百分比（0-100 取整） |

> **精度说明**：整篇文本一次性渲染，浏览器不提供"视口顶部是第几个字符"的信息。当前实现以 `滚动比例 × 全文字符数` 近似换算，恢复误差通常在**半屏以内**。该误差在字号固定的前提下可接受；若未来开放字号调节，需改用 `Range` + 二分查找精确定位。

### 4.5 删除

| 项 | 规格 |
| --- | --- |
| 入口 | 书架卡片右上角 ✕ |
| 行为 | 删除书籍记录并连带清理进度记录（同一事务） |
| 确认 | **当前无二次确认**，点击即删（见 8. 已知风险） |

## 6. 技术方案

### 6.1 架构

```text
┌──────────────┐
│   UI 层       │  Library / Reader（React 组件）
└──────┬───────┘
       │
┌──────▼───────┐
│  数据访问层   │  repo.ts（导入、列表、删除、进度读写）
└──────┬───────┘
       │
┌──────▼───────┐        ┌──────────────────┐
│  纯逻辑层     │        │  存储层           │
│  core/txt.ts │        │  Dexie/IndexedDB │
└──────────────┘        └──────────────────┘
```

分层目的：`core/txt.ts` 不依赖 DOM 与数据库，全部为纯函数，是单元测试的主要覆盖对象。

### 6.2 技术选型

| 层 | 选型 | 选择理由 |
| --- | --- | --- |
| 构建 | Vite 8 | 启动快、零配置 |
| 框架 | React 19 + TypeScript | 类型安全，组件生态成熟 |
| 存储 | Dexie | 对 IndexedDB 的轻量封装，支持版本迁移与事务 |
| 测试 | Vitest + Testing Library | 与 Vite 同源，无需额外构建配置 |
| 测试辅助 | fake-indexeddb | 在 Node 环境模拟 IndexedDB，使数据层可测 |
| 后端 | 无 | 本地优先定位，刻意不引入 |

### 6.3 数据模型

```text
books
├─ id          string   主键（UUID）
├─ title       string   书名（文件名推导）
├─ size        number   文件字节数
├─ encoding    string   'utf-8' | 'gb18030'
├─ charCount   number   全文字符数
├─ text        string   全文内容
└─ createdAt   number   导入时间戳（索引）

progress
├─ bookId      string   主键，对应 books.id
├─ charOffset  number   全文字符偏移
└─ updatedAt   number   更新时间戳
```

索引设计：`books: 'id, createdAt'`、`progress: 'bookId'`。

版本演进：v1 含 `annotations` 表与章节化进度，v2 移除 `annotations` 并将进度简化为单一 `charOffset`。

### 6.4 关键实现

| 关注点 | 实现方式 | 代码位置 |
| --- | --- | --- |
| 编码识别 | 严格 UTF-8 试解 → 失败回退 GB18030 | `src/core/txt.ts` |
| 进度换算 | `ratio = charOffset / charCount`，双向互转 | `src/core/txt.ts` |
| 滚动节流 | 400ms 防抖后写入 IndexedDB | `src/pages/Reader.tsx` |
| 位置恢复 | 内容渲染完成后 `requestAnimationFrame` 内设置 `scrollTop` | `src/pages/Reader.tsx` |
| 事务删除 | `db.transaction('rw', books, progress, ...)` | `src/db/repo.ts` |

### 6.5 编码识别策略

```text
读取 ArrayBuffer
  ├─ 前 3 字节为 EF BB BF → UTF-8（带 BOM）
  ├─ 以 fatal 模式试解 UTF-8 成功 → UTF-8
  └─ 抛错 → GB18030
```

设计理由：UTF-8 的字节序列几乎总能被 GB18030"成功"解码（结果是乱码），因此只能**先假设 UTF-8**，用严格模式证伪，而不是先猜 GBK。

## 7. 非功能需求

| 维度 | 要求 | 现状 |
| --- | --- | --- |
| 隐私 | 数据不出浏览器，无任何网络请求 | ✅ 达成（无后端、无埋点） |
| 启动性能 | 冷启动到可交互 < 1s | ✅ 达成（静态资源 gzip 约 102 KB） |
| 兼容性 | Chrome / Edge / Firefox / Safari 近两年版本 | ⚠️ 依赖 `TextDecoder('gb18030')` 与 IndexedDB |
| 离线可用 | 断网后功能完整 | ✅ 达成（首次加载后完全离线可用） |
| 数据持久性 | 清除浏览器数据前不丢失 | ⚠️ 依赖浏览器存储，无导出能力 |

## 8. 已知限制与风险

| # | 风险 | 影响 | 缓解建议 |
| --- | --- | --- | --- |
| 1 | **大文件无上限** | 全文一次性渲染进 DOM，10MB 级文本可能明显卡顿甚至短时无响应 | 增加导入大小限制（建议 10MB）或分段渲染 |
| 2 | **进度为近似值** | 窗口或字号变化较大时，恢复位置有半屏级偏差 | 改用 Range 二分查找精确字符定位 |
| 3 | **删除无二次确认** | 误触即永久删除书籍与进度 | 增加确认弹窗或撤销提示 |
| 4 | **无导入/导出备份** | 浏览器清理数据后书籍彻底丢失 | 提供书架导出/导入（JSON） |
| 5 | **缺少 E2E 测试** | 真实浏览器中的文件选择、拖拽、滚动恢复未自动化验证 | 引入 Playwright 覆盖核心链路 |
| 6 | **单页渲染内存占用** | 长文本在小内存设备上可能触发回收或卡顿 | 虚拟滚动 / 分段加载 |

## 9. 验收标准

MVP 判定为「可用」需同时满足：

1. 导入 UTF-8 与 GBK 编码的 TXT 各一本，均无乱码，书架显示正确书名与字数
2. 打开任意一本，能连续滚动阅读，段落换行与原文一致
3. 滚动到中段后关闭页面，重新打开并进入该书，位置回到中段附近（误差 ≤ 半屏）
4. 书架正确显示已读百分比，且与进度一致
5. 删除书籍后，书架与进度数据均被清理

当前自动化测试覆盖情况：

| 测试文件 | 覆盖内容 | 用例数 |
| --- | --- | --- |
| `tests/txt.test.ts` | 编码识别、解码、文件名转书名、进度换算 | 15 |
| `tests/repo.test.ts` | 导入、列表排序、进度读写、事务删除 | 7 |
| `tests/app.test.tsx` | 书架空态、书籍卡片渲染 | 2 |

> 验收标准第 1-5 条中的「真实浏览器交互」部分尚无自动化覆盖，需人工验证（见风险 5）。

## 10. 后续规划

| 版本 | 主题 | 内容 |
| --- | --- | --- |
| v0.2 | 稳定性 | 大文件导入限制、删除二次确认、导入失败提示细化 |
